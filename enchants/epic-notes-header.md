# Epic Mystic Enchants: history, logic and testing

This file is generated by `scripts/legendary_history.py --quality Epic`; edit `enchants/epic-notes.csv` (assumptions,
sources, decisions, checked verdicts) or the test results, then run it again. The table of every epic copy (and the
lower-quality copies of the same enchants) is `enchants/epic-history.csv`. Legendaries have their own files
(`enchants/legendary-notes.md`).

## How to read an entry

- **Status**: `changed, awaiting in-game test` means a fix is merged but nobody has reported testing it.
  `tested (see test notes)` means a result is recorded; read it, because a recorded result can be a failure.
  `works from its data` and `handled by the core` mean we checked it and changed nothing. `unchanged: ...` is the
  tracker's audit verdict for a copy nobody has touched.
- **Changes table**: every commit whose added lines mention the enchant's spell id, the pull request that merged it,
  the first published server build that contains it, and the date patch night installed that build on our server.
  A commit can mention an id without changing that enchant (a shared list, for example), and a fix can reach an
  enchant through a different spell id (its proc, summon or transformed spell), so read the logic and pull request
  notes below as well.
- **How a change reaches players**: SQL in `sql/enchants/` is applied by patch night straight from GitHub, so an
  SQL-only change can be live before its build. Anything in `patches/` (the enchant scripts included) needs a server
  build, and is live only once patch night has installed that build.
- **What the server does**: copied from the comments in the enchant scripts and the SQL file headers, which describe
  each enchant's logic in plain English. **What the pull requests said** quotes the pull request descriptions, where
  most assumptions and guesses were written down at the time.
- **Assumptions**: anything we decided without a source (a number, a radius, how two effects interact).
- **Testing**: in-game results from `enchants/test-checklist.csv` and the tracker's tested column, with dates.
  "Nothing recorded yet" is the default; please add results there.

## Sources

1. **Ascension builder tooltips**: the archived Ascension builder (area-52 realm, snapshot of 14 June 2026). The text
   is Ascension's, so it is not kept in this repository; a private copy is on the game server
   (`C:\Games\CoA Server\ascension-mystic-enchants.json`).
2. **Our client's spell data**: Spell.dbc in the client's patches (effects, numbers and the enchant's own text). Where
   the builder has no entry (older or removed enchants), this is the only record.
3. **Core class versions**: several enchants copy a class ability that the CoA core already scripts (Blooming Shot,
   Eternity, Nature's Power); their numbers and behaviour were taken from those.
4. **Player descriptions**: written descriptions from players who used the enchant on Ascension, passed on by James
   in the development chat (Mana Fiend, Steward of Eternity, Grove Ranger's Blooming Shot).
5. **Public pages**: the Project Ascension wiki (Enchant Collection page) and the Ascension forum. Ascension's own
   database (db.ascension.gg) blocks automated reading and its news posts need a browser, so they were not used.
6. **Decisions**: calls James made where the sources disagreed or said nothing (listed under each enchant).

## Process

1. Open epics come from `enchants/tracker.csv` (status broken, partly working or missing, and no fix mentioning them
   yet), sorted by how much work they need: plain hooks and procs first, new spells and transforms last.
2. Fixes go in batches, each its own pull request, starting with epic batch 1 (#178). Every batch is compile-checked
   against the core release the build uses (also with the Windows header macros defined) and its SQL loaded twice
   into a scratch database. None of that replaces in-game testing, which is recorded per enchant below.

## Known core quirk

The core calls the heal hook (`UnitScript::ModifyHealReceived`) with its two units in a different order for direct
heals (healer first) than for heal-over-time ticks (target first). Batch 5 (`sql/enchants/051-epics-5.sql`) added
`WcmeHealParties` to the enchant scripts to put them in the right order, and fixed the rules that had read them
the wrong way round: Holy Ground (81315 / 281788) and the Align heal bonus (986160). (Growing Light, 270661, was the third;
review found the core already does it, so ours is gone.) Any new
heal rule should call `WcmeHealParties` first.

## Overlaps with the core's own enchant code

The core has its own Mystic Enchant system (the `coa_mystic_enchant_*` tables run by `spell_ascension_mystic_enchant_proc`,
and some enchants written into its C++). Where we also scripted an enchant it already handles, the effect happened twice.
`enchants/core-overlap-review.csv` lists every enchant we touch that also appears in the core, with the review result.
Before scripting any enchant, check that file's sources first: the core's tables in `data/sql/updates/pending_db_world`
and its C++ in `src/server` (search for the enchant's spell id).

`enchants/core-rule-gaps.csv` lists enchants the core handles where one trigger effect has no core rule, so that effect
never fires (found while reviewing Searing Flames); most still need a look.

`enchants/core-refresh-aura-review.csv` lists the spells whose "refresh aura" effect (173) carries a time but no "add"
flag. The core then sets the aura's time left to that value instead of adding it, though most of these spells are named
as extensions (found while reviewing Savage Momentum, whose Stampede would drop to 2 sec). 13 are reached by Mystic
Enchants through their data; they still need a look.
